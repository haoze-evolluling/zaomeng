# 插件安装真机验收

先在仓库根目录生成测试包：

```powershell
python scripts/build_plugin_test_packages.py
```

把 `dist/plugin-test-packages` 放到手机文件管理器可访问的位置，然后按顺序验证：

| 测试包 | 预期结果 |
|---|---|
| `01-valid-v1.zip` | 显示插件 ID、v1.0.0 和两项权限；确认后安装成功 |
| `02-update-v2.zip` | 识别为从 v1.0.0 更新到 v2.0.0；确认后更新成功 |
| `03-incompatible-api-v2.zip` | 显示宿主只支持 API 1，并禁止安装 |
| `04-path-traversal.zip` | 检查阶段直接拒绝，应用目录外不得出现 `escape.txt` |
| `05-official-id-collision.zip` | 提示内置插件不能被覆盖，并禁止安装 |
| `06-corrupt.zip` | 提示不是有效 ZIP，不创建插件目录 |

正常包安装后还需验证：

1. 在插件管理页启用“插件验收样例”。
2. 在聊天的“插件”菜单中看到“验收样例”，执行后草稿变为 `fixture-ok`。
3. 修改配置、重启应用，确认插件启用状态和配置仍然保留。
4. 更新到 v2.0.0 后再次执行动作，确认仍然可用。
5. 卸载插件，确认列表和聊天插件菜单中都不再出现；内置插件只有停用，没有卸载按钮。
6. 打开“日志与详情”，确认能看到安装、启用、动作完成事件；异常日志不得包含聊天正文或模型密钥。

自动化回归中的“模拟复制失败”会在更新过程中强制触发异常，并检查 v1.0.0 的目录、启用状态和动作能力都已恢复。
